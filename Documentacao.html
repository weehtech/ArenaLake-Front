Manual do Desenvolvedor — ArenaLake

Documentação técnica abrangente para engenheiros e cientistas de dados sobre arquitetura interna, microserviços Docker Compose, provisionamento dinâmico de clusters, esteira Git e acesso à malha Tailscale.

Tecnologias Utilizadas #

O ArenaLake é uma plataforma de Data Lake plug-and-play focada em pequenas e médias empresas, orquestrada inteiramente via Docker Compose. O backend central é construído em Python utilizando o framework FastAPI para roteamento assíncrono de alta performance e Jinja2 para a renderização das interfaces de usuário.

Através da biblioteca Docker SDK, o sistema provisiona dinamicamente ambientes isolados de desenvolvimento baseados no VS Code (code-server) para cada usuário registrado. O armazenamento de dados é gerenciado pelo MinIO, solução de alto rendimento 100% compatível com a API S3. O processamento distribuído opera sobre um cluster nativo do Apache Spark, enquanto o roteamento perimetral é assegurado pelo Traefik e túneis Tailscale WireGuard.

Nota de Arquitetura Todos os nós computacionais são instanciados sob demanda e compartilham a mesma rede bridge virtual isolada, garantindo latência inferior a 15ms nas trocas internas entre workers Spark e os buckets S3 MinIO.

Estrutura de Diretórios #

A organização do código-fonte segue uma divisão lógica orientada a componentes de infraestrutura e serviços do portal:

/deploy Arquivos de configuração e regras de roteamento dinâmico do Traefik.
/docker Arquivos Dockerfile para Spark Worker e Workspace VS Code.
/portal-compute Diretório principal da aplicação web FastAPI.
/portal-compute/core Lógica de negócios: docker_mgr.py e s3_mgr.py.
/portal-compute/routers Rotas da API REST (api.py) e páginas web Jinja2 (ui.py).
/portal-compute/static Arquivos estáticos de frontend (CSS, JS, imagens do dashboard).
/portal-compute/templates Templates Jinja2 que compõem a interface gráfica (Login, Setup, Dashboard).

Arquitetura de Serviços (Docker Compose) #

Os serviços do ArenaLake operam de forma isolada, comunicando-se através de uma rede bridge interna criptografada:

Serviço Papel Principal Porta Interna
Portal Backend FastAPI e painel de controle do sistema 8000
Traefik Reverse Proxy e gerenciamento de rotas HTTP dinâmicas 80
MinIO Object Storage resiliente compatível com S3 API 9000 (API) / 9001 (Console)
Spark Master Nó orquestrador central do cluster de processamento 7077 / 8080 (UI)
VS Code Workspace Container efêmero de desenvolvimento por usuário 8080
Spark Worker Container efêmero de computação vinculado ao usuário Dinâmica / Bridge

Fluxo de Provisionamento (Workspace) #

O ciclo de vida do ambiente computacional do usuário é orquestrado de forma totalmente automatizada:

1

Seleção de Hardware

O usuário faz login e escolhe o perfil desejado (Standard ou Extreme) na interface de Setup.

2

Validação e Despacho

O backend valida a sessão e despacha ordens à Docker API via SDK Python (docker_mgr.py).

3

Limpeza Preventiva

Containers legados do mesmo usuário são descartados para garantir estado limpo e sem vazamento de memória.

4

Subida do Code-Server & Spark Worker

O container VS Code é ativado com cgroups limitando CPU e RAM, acompanhado de seu Spark Worker associado.

5

Persistência de Volumes & Roteamento

Pastas físicas locais do host são montadas e o Traefik injeta uma rota dinâmica em tempo real no iframe do Dashboard.

Configuração do Ambiente (.env) #

A infraestrutura requer um arquivo .env na raiz do projeto contendo as credenciais de operação:

.env 
# DataLake MinIO
MINIO_ACCESS_KEY=arenalake_local
MINIO_SECRET_KEY=arenalake123
DATALAKE_STORAGE_PATH=.

# Spark Cluster
SPARK_MASTER_URL=spark://spark-master:7077

# Portas do Host
PORTAL_PORT=8000
TRAEFIK_WEB_PORT=80
MINIO_API_PORT=9000
MINIO_CONSOLE_PORT=9001
SPARK_UI_PORT=8080

# Malha de Rede Bridge
WORKSPACE_NETWORK=arenalake-local_arenalake-net

Comandos Úteis de Operação #

Iniciar toda a infraestrutura em background:

$ docker compose up -d

Forçar recompilação das imagens (Portal, Worker, VS Code):

$ docker compose up -d --build

Derrubar serviços e expurgar redes órfãs:

$ docker compose down --remove-orphans

Acompanhar logs do Portal em tempo real:

$ docker logs -f arenalake-prod-portal-1

Acesso à Infraestrutura (Rede Tailscale) #

O ArenaLake utiliza o Tailscale para criar uma rede virtual privada (VPN Mesh) baseada no protocolo WireGuard, com criptografia ponta a ponta. Isso permite que qualquer desenvolvedor da equipe conecte sua máquina local diretamente ao servidor principal (Lenovo - Master Node) sem necessidade de abrir portas no roteador ou configurar firewalls.

Atenção Obrigatória no Ingresso Não crie uma rede nova no aplicativo do Tailscale. Você deve aceitar o convite oficial da rede corporativa utilizando estritamente a autenticação via GitHub.

Passo a Passo de Entrada na Rede:

  1. Download e Instalação: Baixe o cliente em tailscale.com/download.
  2. Link de Ingresso: Acesse o convite seguro: https://login.tailscale.com/a/ecb640001755d
  3. Autenticação com GitHub: Faça login com a conta GitHub da organização.
  4. Validação: O ícone ficará verde e você receberá um IP interno seguro no formato 100.x.x.x.
  5. Primeiro Acesso SSH: No PowerShell ou Terminal, valide sua credencial e redefina a senha padrão:
    > ssh username@100.x.x.x
    # Digite a senha temporária fornecida pelo administrador
    > passwd
    # Atualize para sua senha pessoal segura

Ambiente Local de Testes (WSL2 & Docker) #

Para garantir que novos desenvolvimentos não causem regressão em homologação ou produção, é obrigatório testar as alterações localmente no Windows com o WSL2 (Ubuntu).

1. Ativar WSL2 e Integrar ao Docker Desktop

Abra o PowerShell como Administrador e execute:

wsl --install

Reinicie o computador, abra o Docker Desktop > Settings > Resources > WSL Integration, marque Ubuntu e clique em Apply & Restart.

2. Clonar Repositório e Compilar

git clone https://github.com/L1K3D/arenalake-infra.git
cd arenalake-infra
# Crie o .env local com as credenciais antes de subir
docker compose up -d --build
Serviços Disponíveis Localmente no Navegador
Portal ArenaLake http://localhost:8000 Dashboard principal de desenvolvimento
MinIO Console http://localhost:9001 User: arenalake_local / Pass: arenalake123
Spark UI Monitoring http://localhost:8080 Telemetria de jobs, DAGs e executors
Produtividade: Abrir no VS Code com 1 Comando Dentro da pasta clonada no terminal do WSL, digite code .. O VS Code abrirá conectado diretamente ao subsistema Linux via extensão WSL.

Esteira de Versionamento (Git Flow) #

Para blindar a integridade da plataforma, o servidor Lenovo hospeda dois ambientes distintos em paralelo:

HOMOLOGAÇÃO

Branch develop

Localizada em /opt/arenalake-homolog. Roda na porta 10000 com dados de teste. É aqui que novas features são validadas.

PRODUÇÃO

Branch main

Localizada em /opt/arenalake-prod. Roda na porta 8443. É o ambiente oficial dos clientes, 100% estável e auditado.

Fluxo Diário de Commits e Pull Requests:

git-workflow.sh • Terminal Bash 
# 1. Puxe as atualizações mais recentes de develop
git checkout develop
git pull

# 2. Crie uma branch isolada para a funcionalidade
git checkout -b ftr-minha-nova-funcionalidade

# 3. Adicione arquivos modificados e commite com padrão semântico
git add .
git commit -m "feat: implementa novo seletor de perfil no setup"

# 4. Envie a branch para o repositório remoto
git push origin ftr-minha-nova-funcionalidade
Atualizando o Servidor Lenovo após o Merge: Após a aprovação do Pull Request no GitHub, acerte o servidor via SSH com o comando: cd /opt/arenalake-homolog && git pull && docker compose up -d --build

Mapa de Acesso aos Ambientes (Servidor Lenovo) #

Estando conectado na rede Tailscale, o desenvolvedor pode se comunicar diretamente através do hostname arenalakeserver ou pelo IP interno:

Serviço Endereço de Acesso Observação
Portal ArenaLake https://arenalakeserver.tail8b9a43.ts.net Acesso público criptografado via Funnel
Workspace VS Code ...ts.net:8443 Carregado no iframe do Dashboard
MinIO Console http://arenalakeserver:9001 Apenas via VPN. User: arenalake_prod
Spark Master UI http://arenalakeserver:8080 Apenas via VPN. Cluster monitor

Ambiente de Homologação (Testes)

Serviço Endereço de Acesso Observação
Portal ArenaLake (Homolog) http://arenalakeserver:8081 Via Traefik interno com Tailscale ativo
Workspace VS Code (Homolog) ...ts.net:10000 Túnel externo na porta 10000
MinIO Console (Homolog) http://arenalakeserver:9011 Apenas via VPN. User: arenalake_homolog
Spark Master UI (Homolog) http://arenalakeserver:8090 Apenas via VPN. Monitor do cluster de testes

Dicas de Resolução de Problemas Rápidos

  • 1. MinIO ou Spark não abrem: Certifique-se de que o aplicativo do Tailscale está conectado (ícone verde). Os endereços http://arenalakeserver:... dependem da resolução DNS interna da malha VPN.
  • 2. Falha de DNS do nome da máquina: Substitua o nome arenalakeserver pelo IPv4 direto da máquina Lenovo no Tailscale (exemplo: http://100.115.x.x:9001).
